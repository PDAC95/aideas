scenarios INSERT shape (column order matches the migration):

```sql
INSERT INTO public.scenarios (
    functional_area_id, slug, pain_headline_en, pain_headline_es,
    pain_body_en, pain_body_es, typical_hours_per_week,
    impact_label_en, impact_label_es, sort_order, is_active
) VALUES (
    (SELECT id FROM public.functional_areas WHERE slug = '<area-slug>'),
    '<scenario-slug>', '<headline_en>', '<headline_es>',
    $body_en$<body_en>$body_en$, $body_es$<body_es>$body_es$,
    <hours>::double precision,
    '<impact_en>', '<impact_es>', <sort_order>, true
)
ON CONFLICT (slug) DO UPDATE SET
    functional_area_id     = EXCLUDED.functional_area_id,
    pain_headline_en       = EXCLUDED.pain_headline_en,
    pain_headline_es       = EXCLUDED.pain_headline_es,
    pain_body_en           = EXCLUDED.pain_body_en,
    pain_body_es           = EXCLUDED.pain_body_es,
    typical_hours_per_week = EXCLUDED.typical_hours_per_week,
    impact_label_en        = EXCLUDED.impact_label_en,
    impact_label_es        = EXCLUDED.impact_label_es,
    sort_order             = EXCLUDED.sort_order,
    is_active              = true,
    updated_at             = NOW();
```

scenario_templates INSERT shape (composite PK, no slug):

```sql
INSERT INTO public.scenario_templates (scenario_id, template_id, display_order)
VALUES (
    (SELECT id FROM public.scenarios WHERE slug = '<scenario-slug>'),
    (SELECT id FROM public.automation_templates WHERE slug = '<template-slug>'),
    <display_order>
)
ON CONFLICT (scenario_id, template_id) DO UPDATE SET
    display_order = EXCLUDED.display_order;
```

WHY subquery FK resolution: scenario UUIDs are auto-generated and not stable across `supabase db reset`. Slug-based subquery resolution makes the migration replayable on any fresh DB. Template UUIDs DO exist as hardcoded literals in `supabase/seed.sql` (`ee010100-...`), but seed.sql is local-only demo data. In production the templates may be reseeded; slug-based resolution stays correct in either case.

WHY ON CONFLICT DO UPDATE on scenarios: lets Patrick edit pain copy in the draft + re-run the migration, with edits propagating to the DB without manual cleanup.

WHY ON CONFLICT DO UPDATE on scenario_templates: lets Patrick adjust display_order in the draft + re-run, refreshing the order without duplicate-key errors. ON CONFLICT DO NOTHING would silently ignore reorders.

WHY a separate migration (timestamp 20260517000002, AFTER 20260517000001_functional_areas_seed): functional_areas must exist before the scenarios subquery can resolve. Migration timestamp order = apply order.

WHY dollar-quoted strings for pain_body_*: bodies contain apostrophes ("don't", "it's"). Doubling single quotes is error-prone for multi-paragraph bodies; dollar-quoting with $body_en$...$body_en$ tags (or $sb1$...$sb1$ if any body contains the literal $body_en$) survives any text.
