<objective>
Wire `?org=` parsing into both list pages so the deep-links from `/admin/clients/[id]` actually filter the results, and render a localized filter chip that makes the active org-filter visible + clearable.

Purpose: Plan 01 made the query layer slug-or-uuid aware. This plan exposes that to the user by (a) parsing `?org=` in the page server components, (b) passing it into the queries via the new contract, and (c) rendering a chip — both for the "active filter" state and the "org not found" error state. Closes the visible half of CLNT-04 and AUTM-02.

Output:
- New `<AdminOrgFilterChip>` server component reused by both pages
- Updated `/admin/requests/page.tsx` and `/admin/automations/page.tsx` consuming the new envelope return shape from Plan 01
- New `orgFilter` i18n subtree under `admin.requests.list.*` and `admin.automations.list.*` (EN/ES parity)
</objective>
