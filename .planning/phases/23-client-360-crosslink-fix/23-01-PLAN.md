<objective>
Establish the identifier-resolution contract used by both admin list queries: accept slug-or-uuid for the org filter, resolve internally, and return a structured envelope that includes `resolvedOrg` so the pages (Plan 02) can render the filter chip without an extra round-trip.

Purpose: Today `fetchAdminRequests` ignores `?org=` entirely and `fetchAdminAutomations` treats it as a UUID — passing the slug emitted by the Client 360 tabs returns empty results silently. Centralizing the slug-or-uuid resolution in one helper (consumed by both query files) closes both CLNT-04 and AUTM-02 at the data layer in a single wave and avoids duplicating regex/lookup logic.

Output:
- `web/src/lib/admin/org-identifier.ts` (new shared helper)
- Extended types in `web/src/lib/admin/types.ts` (new envelope shapes — no breaking changes to row types)
- Refactored `fetchAdminRequests` and `fetchAdminAutomations` returning the envelope
</objective>

  <action>
    Create `web/src/lib/admin/org-identifier.ts` with TWO exports:

    1. `export function isUuid(value: string): boolean` — uses the strict RFC 4122 v1-5 regex:
       `/^[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i`
       Returns false on empty/null. Pure function, no I/O.

    2. `export async function resolveOrgIdentifier(supabase, raw)` — takes a Supabase server client and a `string | null | undefined` and returns:
       ```typescript
       type ResolveResult = {
         orgId: string | null;          // UUID to use in .eq("organization_id", ...) — null when not resolvable
         resolvedOrg: { id: string; name: string; slug: string } | null;
         orgIdentifierProvided: string | null; // the raw input, trimmed; null when input was empty
       };
       ```
       Behavior:
       - If raw is null/empty/whitespace-only → return `{ orgId: null, resolvedOrg: null, orgIdentifierProvided: null }`.
       - Trim and cap at 100 chars (defensive — drop everything past char 100 BEFORE the lookup). If cap was hit, still perform the lookup with the truncated value.
       - If `isUuid(trimmed)` → SELECT `id, name, slug` from `organizations` where `id = trimmed AND deleted_at IS NULL` (maybeSingle). If found, return `{ orgId: row.id, resolvedOrg: row, orgIdentifierProvided: trimmed }`. If not found, return `{ orgId: null, resolvedOrg: null, orgIdentifierProvided: trimmed }`.
       - Else (slug path) → SELECT `id, name, slug` from `organizations` where `slug = trimmed AND deleted_at IS NULL` (maybeSingle). Same return shape.
       - On Postgres error: throw (this is unexpected; let the page error boundary handle it). Do NOT swallow.

       Do NOT call `assertPlatformStaff` here — callers (the query functions) already gate. Helper assumes the supabase client is staff-authenticated.

       Type the supabase param as `SupabaseClient` from `@supabase/supabase-js` (import `SupabaseClient` type). Use generic `SupabaseClient` (no Database generic) to keep the helper portable; the row read uses a typed cast on the result.

    3. In `web/src/lib/admin/types.ts`, ADD (do not modify existing exports):
       - `export interface ResolvedOrg { id: string; name: string; slug: string; }`
       - `export interface AdminOrgFilterMeta { resolvedOrg: ResolvedOrg | null; orgIdentifierProvided: string | null; }`
       - `export interface AdminRequestListResult { rows: AdminRequestRow[]; orgFilter: AdminOrgFilterMeta; }`
       - `export interface AdminAutomationListResult { rows: AdminAutomationRow[]; orgFilter: AdminOrgFilterMeta; }`

       Add a JSDoc above `AdminAutomationListFilters` noting that `organizationId` is now interpreted as slug-or-uuid by `fetchAdminAutomations` via `resolveOrgIdentifier`. Do NOT rename the field (deferred per CONTEXT.md).

    No console.log. No `any`. TypeScript strict.

    ```typescript
    export async function fetchAdminRequests(input: {
      tab: AdminRequestTab;
      locale: string;
      orgIdentifier?: string | null;   // NEW — slug-or-uuid; null/undefined = no org filter
    }): Promise<AdminRequestListResult>;
    ```

    Implementation changes:
    - After the `assertPlatformStaff` check, call `const { orgId, resolvedOrg, orgIdentifierProvided } = await resolveOrgIdentifier(supabase, input.orgIdentifier ?? null);`
    - Special case: if `orgIdentifierProvided !== null` AND `orgId === null` (i.e., user gave a value but it didn't resolve to an org) → SKIP the DB list query entirely and return `{ rows: [], orgFilter: { resolvedOrg: null, orgIdentifierProvided } }`. This avoids a pointless full-table scan + makes "org not found" semantically distinct from "no org filter".
    - When `orgId` is present, insert `.eq("organization_id", orgId)` into the filter chain AFTER `.is("deleted_at", null)` and the two translation `.eq` calls, BEFORE `.order(...)`. Match the filter-chain comment style from automation-queries.ts:41-48.
    - Replace the final `return rows.map(...)` with `return { rows: rows.map(...), orgFilter: { resolvedOrg, orgIdentifierProvided } };`. The row mapping logic itself stays IDENTICAL.
