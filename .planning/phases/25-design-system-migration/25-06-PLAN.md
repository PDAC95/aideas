<objective>
Triage and fix the cross-cutting layout shells (customer + admin sidebars and headers, admin layout wrapper) that surfaced as token-leak risks during Plan 25-04. These are NOT full reskins — they are surgical token fixes targeting the surfaces that would otherwise force every UAT route to fail (because every route renders inside one of these shells).

Purpose: Without this plan, the customer dashboard would render orange CTAs and Code Orange tabs inside a shell still using `bg-gray-100` / `bg-gray-950` page bg, creating a visual mismatch. The shells are the "glue" that holds the page together; if they look broken, every screen looks broken. CONTEXT.md scope says composed-component reskins live in Phase 32/33 — but the cross-cutting layout shells are the exception because they're inherited by every screen (UAT-blocking).

Scope:
- Customer dashboard nav + header (sidebar + topbar that wrap every /dashboard/* route).
- Admin layout + admin sidebar + admin header (the shell wrapping every /admin/* route).
- ADMIN badge token consumption verified (RESKIN-06 visual distinction).

- Composed cards inside dashboard sections (KpiCards, ActivityFeed, AutomationList, settings cards, billing cards, etc.).
- Composed admin table cells, detail panes, request modals.
- Charts (Tier 6 Recharts files were addressed in Plan 25-04).
