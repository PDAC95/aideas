Per research Open Question 1 (recommendation: keep dark-themed):

The current `/admin/login` page uses `bg-gray-900` (or similar) to signal "admin context" — visually distinct from the customer login at `/login`. Preserve this distinction by swapping to Factory's dark-base palette HEX values directly (since the page is intentionally dark in BOTH light- and dark-mode and shouldn't use the `bg-background` utility which is light by default).

Read the file. Identify the page wrapper, card wrapper, text classes, border classes:

Apply these inline-HEX swaps (because we cannot use semantic tokens that would flip with theme):
- Page bg `bg-gray-900` / `bg-zinc-900` / `bg-slate-900` → `bg-[#020202]` (Factory dark-base-primary)
- Card bg `bg-gray-800` / `bg-zinc-800` → `bg-[#101010]` (Factory dark-base-secondary)
- Body text `text-white` / `text-gray-100` → `text-[#d6d3d2]` (Factory neutral-100)
- Muted text `text-gray-400` / `text-gray-500` → `text-[#a49d9a]` (Factory neutral-400)
- Border `border-gray-700` / `border-gray-800` → `border-[#3d3a39]` (Factory neutral-800)
- Input bg `bg-gray-800` (when used inside the dark page) → `bg-[#101010]`
- Input border `border-gray-700` → `border-[#3d3a39]`
- Input text `text-white` → `text-[#d6d3d2]`

Keep the CTA Button using the standard Button primitive. The default Button variant is `bg-primary text-primary-foreground` — Code Orange CTA on near-black bg works visually, and the `text-primary-foreground` token correctly resolves to `#ffffff` in light-mode-rendered context, but since this page is forcibly dark via inline HEX, the contrast is pure orange + white text → fine.
