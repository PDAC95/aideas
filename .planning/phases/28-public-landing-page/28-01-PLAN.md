<objective>
Build the SSR foundation for the public landing page: route swap so `/` renders a React Server Component (replacing today's `redirect("/landing/index.html")` rewrite), a `(public)` route group with header + footer + locale switcher, six empty section stub files for waves 2 and 3 to fill, and the full `landing.*` i18n namespace seeded in EN and ES with every scaffolding string and every section title key.

Purpose: Phase 28 cannot ship if the route isn't claimed by Next.js, the next-intl namespace doesn't exist, or there's no place to mount section components. This plan lays all three foundations in a single wave so 28-02 and 28-03 can run in parallel against disjoint section files. By creating section stubs up front, we avoid a `page.tsx` merge conflict between wave-2 plans.

Output:
- `/` route owned by Next.js, SSR-rendering an empty-but-valid React landing page
- 6 section component files exist as stubs (named exports, no content)
- `landing` i18n namespace with header/footer/locale/section-title keys in both locales
- Working locale switcher component
- Middleware no longer rewrites `/` to the static HTML fallback
</objective>

   ```ts
   "use server";
   import { cookies } from "next/headers";
   export async function setLocale(locale: "en" | "es") {
     const store = await cookies();
     store.set("NEXT_LOCALE", locale, {
       path: "/",
       maxAge: 60 * 60 * 24 * 365, // 1 year
       sameSite: "lax",
     });
   }
   ```
