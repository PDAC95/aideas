3. **FaqJsonLd Server Component** (`web/src/components/landing/faq-json-ld.tsx`):

   This component renders a single `<script type="application/ld+json">` tag containing a FAQPage JSON-LD object built from the same `landing.faq.questions.q1..q6` i18n keys FaqSection consumes. Implementation:

   ```tsx
   import { getTranslations } from "next-intl/server";

   const QUESTION_KEYS = ["q1", "q2", "q3", "q4", "q5", "q6"] as const;

   /**
    * SECURITY NOTE: This component renders JSON-LD using React children inside
    * a <script> element. All content comes from server-side i18n keys (en.json
    * / es.json) which are static, version-controlled, and contain no user
    * input — therefore there is no XSS attack surface. We use the React
    * children pattern (NOT dangerouslySetInnerHTML) and rely on
    * JSON.stringify's standard escaping plus a final replace step for the
    * "</" sequence which JSON.stringify does not escape and which could break
    * out of the script tag if it appeared in a value.
    */
   export async function FaqJsonLd() {
     const tq = await getTranslations("landing.faq.questions");
     const payload = {
       "@context": "https://schema.org",
       "@type": "FAQPage",
       mainEntity: QUESTION_KEYS.map((k) => ({
         "@type": "Question",
         name: tq(`${k}.question`),
         acceptedAnswer: {
           "@type": "Answer",
           text: tq(`${k}.answer`),
         },
       })),
     };
     // Escape </ to prevent script-tag breakout — JSON.stringify does not
     // escape this sequence on its own. Belt-and-suspenders even though our
     // content is server-controlled.
     const safeJson = JSON.stringify(payload).replace(/<\//g, "<\\/");
     return (
       <script
         type="application/ld+json"
         // React-children pattern: writes the JSON string as the script's text
         // content. This is the documented safe pattern for JSON-LD in React.
         // Using children (not dangerouslySetInnerHTML) means React handles
         // the text-node insertion and applies standard text encoding.
       >
         {safeJson}
       </script>
     );
   }
   ```

   **Why NOT `dangerouslySetInnerHTML`:** The React children pattern above writes the JSON string as a text node child of the `<script>` element. React's standard text-node rendering handles escaping correctly here because the parent element is `<script>` (which treats children as raw text); React does NOT HTML-escape inside `<script>` and JSON.stringify produces valid JSON-LD that browsers parse correctly. The `</` escape is the one edge case JSON.stringify misses for `<script>` embedding, and we patch it explicitly. This pattern is documented by Google (https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data) and by Next.js for static JSON-LD.
